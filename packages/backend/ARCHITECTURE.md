# Backend placement decision

1. **Shared policy, Convex persistence (chosen).** `@vakil/domain` contains platform-neutral constants, limits, error codes, and lifecycle policy. Convex owns validators, identity, private reads, transactional reservations, scheduling, storage, and provider actions. Mobile clients can reuse policy without importing server code. Cost: validators still belong at the Convex boundary.
2. **Convex-centric domain.** Keep all policy and validators next to schema and export inferred Convex types to every client. Fewer modules initially, but React Native and other consumers become coupled to database IDs, storage shapes, and Convex runtime semantics.

Convex hosted persistence and Clerk identity are decided. An action is the only external AI/storage-content boundary. Mutations own all durable decisions. Booking requests atomically claim a slot, persist the caller's explicit recipient consent and a summary snapshot, and schedule expiry at `min(slot.start, request.time + 24h)`. Requests do not silently become accepted consultations. Profiles edited after approval require review again; suspended profiles stay suspended until explicit administrator approval. No credentials or private case data appear in discovery.

Generated API/server bindings use the installed Convex CLI or its pinned application templates; local data model aliases derive from schema. Hosted codegen becomes authoritative after provisioning. Tests use convex-test against actual registered functions; their concurrency evidence is local harness evidence, not a certification of hosted Convex OCC. Hosted Clerk, storage, scheduler, and DGX acceptance remain separate deployment checks.

Discovery ranks the complete eligible set within a bounded pilot cohort of 500 approved profiles (or the selected city's cohort). Expertise and language filters stay strict, then future availability and deterministic name/ID ties determine order. Cursors describe live ranked offsets and are bound to the filters. Exceeding the cohort limit produces an explicit error; scaling beyond it requires an indexed discovery projection rather than an unbounded scan. Reactive availability can change ordering as reservations change.

Administrative profile queues accept an explicit status, so approval does not remove the suspension/reapproval path from the website. Account management receives only operational metadata, never Clerk subjects or private case text. Participant cancellation requires a future slot; explicit administrative handling remains separate.

Accepted consultations survive profile edits, credential changes, suspension, and account disablement. The booking retains its reservation and gains unresolved admin handling; pending requests close. Admins get an operational queue without private summaries and explicitly cancel or retain a booking with a reason. Retention requires reactivated participants and renewed advocate approval. Participant cancellation remains an explicit decision; unresolved handling blocks completion. Every request, state change, affected flag, and admin decision writes a durable event in the same transaction as the decision.

Profiles declare approved consultation modes. Slots select one of those modes, discovery exposes it, and booking mutations copy it from the slot. A profile change never rewrites a booked mode or summary snapshot. Newly unsupported modes disappear from public availability and cannot be reserved.

Reviewed follow-ups append only to the caller's case, retain the newest context within count and character limits, and preserve the case locale. A context revision protects both append races and provider persistence. The server rechecks account/ownership, summary version, and context revision after external inference. Unknown/emergency urgency values remain preliminary labels with no emergency connection guarantee.

Credential content crosses an authenticated action boundary without bearer URLs. Upload checks byte signatures before storage, while the attach mutation checks capacity and storage size/MIME metadata. MIME metadata is optional in Convex storage; an explicitly conflicting value is rejected. Failed attachment deletes its uploaded blob. Public discovery and administrative booking handling omit credential contents and case summaries.
