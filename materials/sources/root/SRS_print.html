1. Introduction & Executive Scope

Vakil Setu is an AI-powered, voice-first legal triage platform designed to bridge the first-mile justice divide in India. The software accepts spoken Hindi or English descriptions of legal disputes, classifies grievances into canonical legal domains (Criminal, Civil, Family, Property), assesses statutory urgency, vocalizes plain-language procedural guidance for low-literacy citizens, matches users with verified enrolled advocates, and coordinates appointment scheduling backed by cryptographic Razorpay payment verification.

3. Technical Architecture & System Design

  • Client Layer: React 18 SPA (Vite), W3C Web Speech API (zero-cost client STT/TTS), AppContext state management.
  • API Gateway: Node.js (v20+ LTS) + Express.js RESTful routing, CORS security, custom error middleware.
  • AI Intelligence Layer: Dual-engine pipeline: Google Gemini 2.0 / Gateway LLM + Local regex heuristics failover engine.
  • Data Persistence: MongoDB Atlas via Mongoose ODM (Advocate, Booking, User schemas); Cheerio web crawler.
  • Payment Security: Razorpay API with server-side HMAC SHA-256 cryptographic signature recalculation.

4. Core Functional Requirements (FR)

  • [FR-1.1: Hands-Free Voice Ingestion] The system SHALL capture spoken audio in real-time using browser SpeechRecognition without server-side audio upload overhead.
  • [FR-1.2: Bilingual Locale Tagging] The system SHALL support hi-IN and en-IN recognition with dynamic BCP-47 locale tagging.
  • [FR-1.4: Direct Text Fallback] The system SHALL provide a manual text entry area on all triage interfaces for users on desktop PCs.
  • [FR-1.5: Accessibility Speech Synthesis] The system SHALL vocalize generated legal summaries aloud via window.speechSynthesis in regional accents.
  • [FR-2.1: Statutory Domain Triage] The system SHALL classify grievances into exactly one canonical domain: criminal, civil, family, or property.
  • [FR-2.2: Procedural Urgency Estimation] The system SHALL assign an urgency rating (low, medium, high, emergency) based on statutory limitation deadlines.
  • [FR-2.4: Deterministic Rule Failover] If upstream LLM endpoints return HTTP 429/503, the system SHALL route the narrative through local regex heuristics with zero downtime.
  • [FR-3.1: Algorithmic Advocate Matching] The system SHALL query MongoDB for active advocates matching the classified domain, sorted by rating descending.
  • [FR-4.1: Consultation Scheduling & Escrow] Litigants SHALL schedule consultation appointments with server-side Razorpay order generation and HMAC SHA-256 signature verification.
  • [FR-5.1: Instant Legal SOS Hub] The emergency workflow SHALL render direct 1-tap call triggers to 112 (Police), 1091 (Women Helpline), and 15100 (NALSA Free Legal Aid).

5. Non-Functional Requirements (NFR)

  • [NFR-PERF-1: Speech Latency] Interim speech-to-text tokens SHALL render within 200ms on client devices.
  • [NFR-PERF-2: Triage Response Time] End-to-end AI triage processing round-trip SHALL complete within 3.5 seconds.
  • [NFR-REL-1: Failover Speed] Deterministic regex failover execution SHALL execute within 50ms upon upstream timeout detection.
  • [NFR-SEC-1: Cryptographic Integrity] All financial transactions SHALL be validated using server-side HMAC SHA-256 signature verification.
  • [NFR-SEC-2: Data Privacy & DPDP Act] Sensitive case descriptions SHALL remain stored in client LocalStorage; no unencrypted personal litigation narratives SHALL be retained in the database.
